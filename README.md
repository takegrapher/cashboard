# cashboard — フリーキャッシュ・シミュレーター（Google スプレッドシート＋Apps Script）

先月・今月・来月以降17ヶ月（計19ヶ月）の入出金を、全費目についてスプレッドシート形式で入力・表示し、
入金計・出金計 → 月末残高（フリーキャッシュ）→ ランウェイ を通算表示するシミュレーターです。
UI もDB（テーブル）も、1つのスプレッドシートファイルの中にあります。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `src/Engine.js` | 計算エンジン（シートAPIに依存しない純粋関数。Node.js でもテスト可能） |
| `src/Schema.js` | DBシート（テーブル）の列定義・プルダウンの選択肢 |
| `src/Sample.js` | 初期設定で投入するサンプルデータ |
| `src/Code.js` | シートの読み書き・グリッド描画・直接入力の取り込み・ダッシュボード・月初処理・メニュー |
| `src/Logo.js` | ロゴ画像（`assets/cashboard_logo_small.jpg` を Base64 にしたもの）。C1 に表示し、クリックで再計算 |
| `assets/` | ロゴ画像（元画像と、埋め込み用に縮小した JPEG） |
| `src/appsscript.json` | Apps Script のマニフェスト（タイムゾーン Asia/Tokyo、V8） |
| `test/engine.test.js` | エンジンの検証（24項目） |
| `test/gas-mock.test.js` | GAS層の検証（SpreadsheetApp のモックで初期設定→描画→上書き→解除） |

## 導入手順（10分程度）

1. Google ドライブで **新しいスプレッドシート** を作成する（名前は任意）。
2. メニュー **拡張機能 → Apps Script** を開く。
3. 最初からある `コード.gs` を削除し、**＋ → スクリプト** で次の5ファイルを作って中身を貼り付ける（名前は任意だが、この順に並べる）。
   `Engine` ← `src/Engine.js`、`Schema` ← `src/Schema.js`、`Sample` ← `src/Sample.js`、`Logo` ← `src/Logo.js`、`Code` ← `src/Code.js`
   （5ファイルを順につなげて1つのファイルに貼り付けても動きます）
4. 左の ⚙「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` を `src/appsscript.json` の内容に置き換える（タイムゾーンを Asia/Tokyo にするため）。
5. 保存（Ctrl+S）してスプレッドシートのタブに戻り、**ページを再読み込み**する。
6. メニューに出る **cashboard → 初期設定（シート作成・トリガー登録）** を実行し、権限を承認する。
   サンプルデータ入りで全シートが作られ、編集トリガーが登録されます。
7. 共有：経営者・経理は「編集者」、閲覧だけの人は「閲覧者」で共有する。
   ※編集トリガーは初期設定を実行した人の権限で動きます。他の編集者は、メニューを初めて使うときに一度だけ承認画面が出ます。

> clasp を使う場合は `src/` をそのまま `clasp push` できます（`.clasp.json` の `rootDir` を `src` に）。

## シート一覧

| シート | 種類 | 役割 |
|---|---|---|
| **シミュレーター** | UI | 模範例「キャッシュフロー」準拠のグリッド（セクション帯／大分類・中分類・明細の3階層／構成比・合計・計上✔/✗／19ヶ月）。小計・集計は数式、表示単位は千円 |
| **ダッシュボード** | UI | 模範例「Dashboard全体／入金／出金」の形式で、1画面に1つずつ表示。B1のプルダウンで全体・入金・出金を切り替え、A列のチェックでグラフに描く系列を選ぶ（A2は全選択／全解除、選択はダッシュボードごとに保持）。表は「シミュレーター」のセルを参照する数式、グラフは非表示シート「_グラフ用」に選択行を並べて描く複合グラフ（全体＝正味FCが棒、入金・出金＝大分類が棒・中分類が折れ線） |
| 科目 | DB | 区分（月初残高／現金同等物／入金／出金）・大分類・中分類・財務区分（営業／出資／融資）・並び順・既定税区分・説明 |
| 取引先 | DB | 締め日・サイト（入金・支払サイトを取引先ごとに設定） |
| 項目 | DB | グリッドの行になる項目。計算種別（明細/固定額/人件費/比率）、開始月・終了月、タグなど |
| 人件費 | DB | 人件費項目の月給・賞与・社保率・源泉税率・住民税 |
| 連動ルール | DB | 「項目が増えたら別の項目を自動生成する」ルール |
| 明細 | DB | 取引明細（実績・予定）と、グリッド上の上書き。1行1取引 |
| パラメータ | DB | 基準月、決算月、残高、税率、納期特例、前期の消費税額など |
| CALC_展開結果 | 自動 | セルごとの計算根拠（内訳表示に使用）。手で編集しない |
| _表示状態（非表示） | 自動 | 前回シミュレーターに表示した値。再計算時に今の値と比べて、直接入力されたセルを検出する |
| 変更ログ / スナップショット | 自動 | グリッド上の変更履歴 / 保存した計画の版 |

### 再計算のタイミング

- セルを編集しても、その場では再計算しません（連続して入力しても妨げにならないように）。2行目に「⏳ 未反映の変更があります」と表示されます。
- 集計に反映されるのは、**メニュー「再計算」を実行したとき（C1 のロゴをクリックしても同じ）**、または**操作をやめて約1分たったとき**（1分ごとの自動再計算）です。
  パラメータ「自動再計算」を「しない」にすると、メニューから実行したときだけ反映します。
- シミュレーター上で直接入力した値は、再計算の直前に「前回表示した値」との差分から取り込みます。
  素早く続けて入力して編集トリガーが発火しなかった場合も、取りこぼしません。

## 使い方

- **項目を追加する**：「項目」シートに1行追加（例：`I024 / B01 / エンジニア_3 / 人件費 / 開始月 2027-10 / タグ エンジニア`）し、
  「人件費」シートに月給などを入れる → 連動ルールにより貸与PC・SaaSライセンス・社保・源泉なども自動で増える。
  行を消すか「有効」のチェックを外すと、連動して生成された行も消える。
- **取引明細を入れる**：「明細」シートに `項目ID・種別・発生日・金額（税抜）` を入力。入出金月は取引先の締め日・サイトから自動計算
  （明示したいときは「入出金月」に入力）。明細ID・登録者・登録日時は自動で入る。
- **グリッドで直接直す**：今月以降の月セルに金額（千円）を入力 → 再計算後にそのセルは黄色（上書き）になり、ルールの値より優先される。
  セルを空にするとルールの値に戻る。先月（実績月）は直接入力できない（明細に実績として登録）。
- **内訳を見る**：月セルを選択して メニュー → 選択セルの内訳を表示（どのルール・明細から来た値かを表示）。
- **月が替わったら（月初処理）**：メニュー **cashboard → 月初処理（1か月進める）…** を実行する。カレンダーの月が変わっても表は勝手には進まない
  （パラメータ「基準月」は最初の再計算で今日の月に固定される。未実施なら2行目に「⚠ 月初処理が未実施です」と出る）。ダイアログで次を行う。
  1. 今月（N列）の値をその月の「実績」として確定する（明細シートに差額の実績行を追加）→ 進めたあとの先月（M列）に処理前のN列の値が入る
  2. 口座ごとの月初残高（今の時点の実際の残高、円）を入力する（シミュレーター上の見込み額も表示）
  3. 基準月を1か月進める（M2〜AE2 の年月がすべて＋1か月）
  4. 新しい最終月（AE列）は各項目のルールで推計した値を表示。行ごとに直した値は「上書き」として保存する
- **見込み案件を試算する**：K列（計上）のチェックを外すと、値は表示したまま合計・消費税・連動・比率の対象から外れる。
  切り替え前に メニュー → スナップショットを保存 で計画を残しておくと、後から予実比較に使える。

### セルの値が決まる順番

| 月 | 値 |
|---|---|
| 先月 | 実績明細のみ |
| 今月以降 | 上書き ＞ 実績＋予定明細 ＞ ルール値＋予定明細（その月に実績が1件でもあれば、ルール値は実績に置き換わる） |

背景色：灰＝実績／薄灰＝実績＋予定／黄＝上書き／薄青＝今月の列。文字色：青＝ユーザーが入力する明細項目の行／黒＝集計・小計・連動・自動計算の行／赤＝マイナス。
罫線：すべて細線。セクション帯は黒、C列（大分類・集計の主項目）の行は黒の細線、D/E列（中分類・明細）の行は灰色の細線。

集計の定義：月初残高＝今月初（＝先月末）の実際の残高（先月の列に表示。先月の入出金はこの残高に反映済みとして積み上げない）／正味フリーキャッシュ＝月初残高＋今月からの入金累計−出金累計＋現金同等物／burn rate＝今月以降の出金の加重平均（当月1.0、1ヶ月遡るごとに0.1減、最大10ヶ月）／ランウェイ＝正味フリーキャッシュ÷burn rate／出資除く・出資・融資除く＝表示期間内の調達額の累計を差し引いた値。

## 計算ルールの仕様

| 計算種別 | 内容 |
|---|---|
| 明細 | 明細シートの金額だけで決まる（顧客別・請求単位の売上など） |
| 固定額 | 金額 × 周期（毎月／指定月 例 `1,4,7,10`／一括＝開始月に1回）。取引先があればサイト分ずらす |
| 人件費 | 手取り（額面−本人社保−源泉−住民税）を支給月に、社保（会社＋本人）を翌月、源泉・住民税を翌月（納期特例なら1月・7月／6月・12月）に計上。賞与月は賞与込み |
| 比率 | 比率対象（`#タグ`・科目ID・項目ID）の同じ月の値 × 比率（決済手数料など） |
| 連動ルール | 条件（科目ID・タグ）に合う項目ごとに行を自動生成。タイミング＝開始月（1回）／毎月／終了月、ずらし月数も指定可 |

**消費税（原則課税）**
- 明細・項目の金額は税抜。税区分（課税10%・課税8%・非課税・対象外）に応じて、入金側は「仮受消費税」、出金側は「仮払消費税」として入出金月に計上。
- 年税額＝課税期間（決算月で決まる）の発生ベースの（仮受−仮払）。表示期間より前の当期分はパラメータ「当期窓前消費税累計」で補う。
- 中間納付：前期の年税額（国税分＝年税額×78/100）で回数を自動判定（48万円超で1回、400万円超で3回、4,800万円超で11回）。パラメータで当期分だけ回数を指定することもできる。
- 確定申告：決算月の2ヶ月後に「年税額−中間納付額」（マイナスなら還付として負の出金）。前期分はパラメータ「前期確定申告納付額」。

**ランウェイ**＝月末残高 ÷ 直近Nヶ月（パラメータ）の平均純減額。純減がなければ「黒字」。

## 簡略化している点（必要に応じて精緻化できます）

- 源泉所得税は税額表ではなく「(額面−本人社保)×率」の簡易計算。社保は「額面×率」で、標準報酬月額の等級・上限は考慮しない。
- 雇用保険・労働保険の年度更新は対象外（必要なら固定額の項目で入れる）。
- 消費税の端数は100円未満切り捨て。中間納付11回のときの初回の納期は簡略化している（毎月の2ヶ月後）。
- 比率項目は1段だけ（比率項目を別の比率項目の対象にはできない）。
- 人件費の手取り行を上書きしても、社保・源泉の行は人件費シートの値のまま。
- 計算は月単位（日単位の資金繰りはしない）。
